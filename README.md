# chua_portfolio

Personal portfolio site for **Kyla G. Chua**: a single page with a hero, a filterable project grid with previews, experience, skills, and contact details.

This README is the handover guide. It covers how the app is put together, where each piece of content lives, and how to change, run, and deploy it.

---

## Quick start

Requirements: **Node.js 20+** and **pnpm** (the repo pins `pnpm@12.3.4` in `package.json`; if `pnpm` isn't installed, `npx pnpm@12.3.4 <command>` works too).

```bash
pnpm install      # install dependencies
pnpm dev          # local dev server at http://localhost:3000
pnpm build        # production build (what Vercel runs)
pnpm start        # serve the production build locally
```

> **Windows note:** if `pnpm build` fails with *"Turbopack is not supported on this platform… native bindings are not available"* or *"An Application Control policy has blocked this file"*, Windows is blocking Next.js's native compiler. Use `pnpm exec next build --webpack` locally instead. Vercel builds on Linux and isn't affected.

## Project structure

```
app/
  layout.tsx        <html> shell: fonts, <title>/SEO metadata, browser theme color,
                    the no-flash dark-mode script, Vercel Analytics
  page.tsx          Renders <Portfolio /> and nothing else
  globals.css       Every style on the site, including the color palette

components/
  portfolio.tsx     The whole page: header, hero, projects, experience,
                    skills, contact, footer, project modal, toast
  ui/button.tsx     shadcn button (scaffolded, currently unused)

data/
  profile.ts        Personal info, skills, and experience  <- edit content here
  projects.ts       The project list                       <- edit projects here

lib/utils.ts        cn() class-name helper used by shadcn components

public/             Served as-is from the site root ("/")
  kyla-chua.jpg       Hero photo        (referenced in data/profile.ts)
  Kyla-Chua-CV.pdf    Downloadable CV   (referenced in data/profile.ts)
  projects/           Put project cover images here
  icon*.png/svg, apple-icon.png   Favicons
  placeholder*        Unused v0 template leftovers, safe to delete

next.config.mjs     Next.js config (see "Configuration" below)
pnpm-workspace.yaml pnpm settings
AGENTS.md           Auto-generated by Next.js for AI coding tools; leave it alone
```

### How the page is put together

- **Content is separate from layout.** `components/portfolio.tsx` only reads from `data/profile.ts` and `data/projects.ts`. Most content updates touch only those two files.
- **The page is one client component** (`'use client'`) because of its interactions: theme toggle, mobile menu, project filters, the project preview `<dialog>`, the experience accordion, copy-to-clipboard toast, photo tilt, and scroll-reveal animations.
- **Styles use readable class names** (`.hero`, `.project`, `.exp-head`, …) defined in `app/globals.css`, organised under `/* ---------- Section ---------- */` headings that follow the page order. To restyle something, inspect the element in the browser, copy its class name, and search for it in `globals.css`.

## Common changes

### Add, edit, or remove a project

Edit the `projects` array in **`data/projects.ts`**. A copy-paste template is in the comment at the top of that file. The grid, filter chips, counts, and preview modal all update automatically.

```ts
{
  title: 'Inventory Dashboard',
  kind: 'web',                               // 'figma' | 'web' | 'docs'
  summary: 'One or two sentences on what it is and what you did.',
  tags: ['React', 'Firebase'],
  year: '2026',                              // optional
  status: 'In progress',                     // optional; omit once finished
  image: '/projects/inventory.png',          // optional; file goes in public/projects/
  live: 'https://inventory.vercel.app',      // optional: "Live site" link
  repo: 'https://github.com/chua05/inventory', // optional: "Code" link
  figma: 'https://www.figma.com/design/…',  // optional: link + live embed in the modal
},
```

- **Order:** projects appear in the order they're listed.
- **Links:** `live`, `repo`, and `figma` each add a button on the card and in the modal. With none set, the modal says "Links coming soon."
- **Figma embeds:** paste the normal Figma share URL. The file's sharing setting must be "Anyone with the link can view" for the embed to load.
- **Cover image:** without `image`, the card draws a generated illustration based on `kind`. Landscape images around 16:10 (for example 1600×1000) fit best.

### Add a new project category (kind)

1. In `data/projects.ts`, add the kind to `ProjectKind` (for example `'figma' | 'web' | 'docs' | 'mobile'`) and give it a label in `kindLabels`.
2. In `app/globals.css`, give it a color by copying the existing `docs` rules and renaming them: `.chip-mobile.active`, `.kind-mobile`, `.pill-mobile`.
3. Optional: give it a generated cover. Add a branch in `ProjectCover` in `components/portfolio.tsx` and an `.art-mobile` style. Otherwise, always set `image` for projects of that kind.

### Update personal info, contact details, CV, or photo

Everything is in **`data/profile.ts`** → `profile`: name, email, phone (`phoneDisplay` is what's shown and `phoneHref` is the `tel:` link), GitHub, location, school, degree, and what she's looking for.

- **New CV:** replace `public/Kyla-Chua-CV.pdf` with a file of the same name. If you rename it, update `profile.cv`.
- **New photo:** replace `public/kyla-chua.jpg` (portrait, about 4:5). It's also the social-share image in `app/layout.tsx`.

### Update skills or experience

Also in **`data/profile.ts`**:
- `skillGroups`: each `{ label, items }` becomes one card in the Skills section.
- `experience`: each entry becomes one accordion row. `status` is optional, and `points` are the bullet lines.

### Change text that isn't in `data/`

A few strings are written directly in **`components/portfolio.tsx`**:

| Text | Where to find it |
| --- | --- |
| Big hero name (`Kyla` / `Chua.`) | the `<h1>` in the hero section |
| Hero intro paragraph | `className="hero-lede"` |
| Spinning badge text | `<textPath>` inside `.badge` |
| Photo stickers (`BSIT ’27`, `Bulan, Sorsogon`) | `sticker-a` / `sticker-b` |
| Section headings (`Things I've designed & built.`…) | each `section-head` `<h2>` |
| Contact heading | `<h2>` inside `#contact` |
| Nav links | `navLinks` at the top of the file |

The browser tab title, search description, and link-preview text are in `metadata` in **`app/layout.tsx`**.

### Change colors (palette)

The palette is a set of CSS variables at the top of **`app/globals.css`**: one block for light mode (`:root`) and one for dark mode (`:root[data-theme='dark']`). Change the values there and the whole site follows.

The current theme is **purple and black**. The variable names come from the original template and no longer describe their colors:

| Variable | Used for | Current light / dark |
| --- | --- | --- |
| `--paper`, `--paper-2`, `--card` | page background, hover fills, card surfaces | pale lavender / near-black |
| `--ink`, `--ink-soft`, `--muted` | main text, body text, secondary text | near-black / pale lavender |
| `--line` | borders | |
| `--tomato` | **main accent**: primary buttons, logo dot, Figma projects | `#7c3aed` / `#a855f7` |
| `--cobalt` | second accent: Web projects, badge, focus ring | `#4c1d95` / `#8b7bff` |
| `--butter` | highlights: text marker, photo backdrop, toast, education card | `#d8b4fe` (both) |
| `--leaf` | third accent: Docs projects, "available" dot | `#a21caf` / `#e879f9` |
| `--on-accent` | text on top of accent-colored backgrounds | |

When changing colors, also update `themeColor` in `app/layout.tsx` (it colors the mobile browser bar) to match `--paper`. A handful of `#0e0b14` values in `globals.css` are a fixed dark text color for use on the always-light `--butter` backgrounds.

### Change fonts

Fonts are loaded in `app/layout.tsx` with `next/font/google`. Swap the imported font names; the CSS variables (`--font-display`, `--font-body`, `--font-mono`) stay the same.

### Dark mode

The sun/moon button toggles `data-theme="dark"` on `<html>` and remembers the choice in `localStorage`. On the first visit it follows the system setting. A small inline script in `app/layout.tsx` applies the theme before the page paints, which prevents a flash of the wrong theme.

## Configuration

`next.config.mjs`:
- `typescript.ignoreBuildErrors: true`: type errors **don't** fail the build. Run `pnpm exec tsc --noEmit` to check types manually.
- `images.unoptimized: true`: images are served as-is, with no Next.js image optimization.
- `experimental.agentUpgrade: "security"`: tells Next.js upgrade tooling to stay on security updates.

`pnpm-workspace.yaml` sets `pmOnFail: ignore` (a different local pnpm version won't error) and exempts `next` / `@next/*` from pnpm's minimum-release-age delay so security patches can be installed right away.

## Deployment (Vercel)

The site is built for [Vercel](https://vercel.com) and needs no environment variables.

**Recommended:** connect the GitHub repo once at [vercel.com/new](https://vercel.com/new). Vercel detects Next.js automatically, and every push to `main` then deploys to production on its own.

**From the CLI:**
```bash
npm i -g vercel
vercel login
vercel --prod
```

### Handing the site to a new owner

1. **GitHub:** transfer the repository (*Settings → General → Transfer ownership*) or add the new owner as a collaborator.
2. **Vercel:** transfer the project (*Project → Settings → General → Transfer*) or have the new owner import the repo into their own Vercel account. A fresh import gets a new `*.vercel.app` URL.
3. **Custom domain** (if any): move it in Vercel under *Settings → Domains*, and update DNS at the registrar if the domain changes hands.
4. **Personal details:** check `data/profile.ts`, `public/Kyla-Chua-CV.pdf`, and `public/kyla-chua.jpg`. The CV, photo, email, and phone number are all public on the site and in the repo.

## Maintenance

- **Updating Next.js:** `pnpm add next@<version> --save-exact`, then `pnpm build` to check. Patch updates within 16.x need no code changes. For major versions, follow the official upgrade guide.
- **Security advisories:** run `pnpm audit` occasionally and update the affected package.
- **Before pushing:** run `pnpm build` (or the `--webpack` variant on Windows) to catch errors before Vercel does.
